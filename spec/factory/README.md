# Factory pack

The default content that ships with the studio. It is ordinary shared content: the same schemas, the same checks, read-only to banks. Part 12 of the design spec says what it is for; Annexes A and D describe what is in it.

## Layout

```
factory/
  p/            the platform: lifecycle blocks, platform workflows, ports and simulators
  uae.p/        the UAE cluster platform: blocks and rules every UAE scheme can use
  uae.wps/      the Wages Protection System: legs, maps, rules, simulators, scheme manifest
  inventory.yaml   the packs of the factory; check L34 holds `factory/` to this list
examples/
  bank/         an example tenant: one hook of each type, its blocks, and a configuration set
  bindings/     one engine binding per target
  supersession/ one supersession
```

Each pack folder holds `activities/`, `rules/`, `ports/`, `simulators/`, `workflows/` (legs, handlers and the subflows behind composite activities), `tests/` and, where it applies, `extensions/`, `hooks/` and `scheme.yaml`. `pack.yaml` is the manifest and lock file: every artefact with its release and hash.

## What is written by hand and what is generated

| Written by hand | Generated by `tools/build_factory.py` |
| --- | --- |
| Workflows, legs, segments, handlers and subflows | Activities, rules, rule sets, decision tables |
| `scheme.yaml` | Ports, simulators, extensions |
| Hooks and the configuration set of the example bank | Tests |
| Engine bindings and the supersession example | `pack.yaml` and `inventory.yaml` |

A generated file says so on its first line. Change the generator, then run it. The generator removes a generated file it no longer emits, so a pack never keeps a stale artefact.

## To add or change something

1. For a generated kind, add or change the entry in `tools/build_factory.py`. For a workflow or a scheme manifest, edit the YAML.
2. `python3 tools/build_factory.py`
3. `python3 tools/validate.py`
4. `python3 tools/expand.py`
5. `python3 tools/mutation_tests.py`
6. `python3 tools/build_docs.py`

A new block that no workflow calls is reported by check L11. Wire it into a workflow, declare `invokedBy: front-door` or `invokedBy: schedule`, or do not add it.

## Status

Every artefact carries `provenance.status`.

| Status | Meaning | Where |
| --- | --- | --- |
| `confirmed` | Follows the north-star architecture and public ISO 20022 practice | `p`, `uae.p` |
| `provisional` | Written from public sources. Not checked against the scheme rulebook | `uae.wps` |

The scheme manifest lists messages as `planned`. A pack with a planned message is not publishable for that message group; the validator says so as a warning.

What does not exist yet: scripts-behind, sample messages, and the kit's own workflows. Tests name their samples and their expected traces; nothing has run them. Part 12, section 12.6 lists every known gap.
