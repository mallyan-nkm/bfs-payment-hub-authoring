# Part 12. Factory pack

Status: draft 0.1, 17 November 2026. Normative words follow RFC 2119.

## 12.1 Purpose

The factory pack is the default content that ships with the studio: the platform (`p`), the UAE cluster platform (`uae.p`), and two schemes (`uae.wps`, `uae.aani`). It gives a designer something real to open on day one, it is the worked example behind every part of this spec, and it is the fixture set for building the studio.

## 12.2 What it is and is not

| It is | It is not |
| --- | --- |
| Shared content with `origin: factory`, held to the same schemas and checks as any other | A separate mechanism or a special kind of artefact |
| Read-only to banks, like all shared content | A bank's content; a bank adds hooks and values on top |
| A complete set of contracts, rules, simulators, workflows and tests | A set of finished scripts; scripts-behind are authored against these contracts (C24 to C26) |
| Confirmed for `p` and `uae.p` | Confirmed for the schemes; `uae.wps` and `uae.aani` are provisional until checked against the rulebooks |

## 12.3 Requirements

| Id | Requirement | Check |
| --- | --- | --- |
| R-12-01 | Every factory artefact MUST validate against its schema and pass every static check. | `python3 tools/validate.py` exits 0 |
| R-12-02 | Every factory artefact MUST carry `provenance.origin: factory` and a status. | Schema (L00) |
| R-12-03 | Scheme content taken from public sources MUST be marked `provisional`, with the source and what to confirm. | Review |
| R-12-04 | Factory content MUST obey the scope rules. `p` names no cluster or scheme; `uae.p` names no scheme. | Lint L02 |
| R-12-05 | Factory content MUST be bank-neutral. Bank values are parameters with defaults. | Lint L09 |
| R-12-06 | Every factory activity MUST have, before the pack is released: a script-behind or a builtin binding, one test per outcome, and a simulator for each port. | Publish check (C24 to C26) |
| R-12-07 | Every factory workflow MUST have at least one test per exit outcome. | Publish check (C24 to C26) |
| R-12-08 | The factory pack MUST include an example bank tenant that shows one hook of each type and a configuration set. The example is not shipped to banks. | `examples/bank/` validates |
| R-12-09 | The factory pack is regenerated by `tools/build_factory.py` for its repetitive parts. Generated files MUST NOT be edited by hand. | File header; review |
| R-12-10 | A scheme pack MUST list every message of the scheme, including those not yet built, as `planned`. | Lint L10 |

## 12.4 Contents

The pack is checked by three tools. `tools/validate.py` runs the schemas and the checks of Part 5. `tools/mutation_tests.py` breaks the pack once per check and expects the check to fire. `tools/build_docs.py` refuses to render if a build story cites an artefact, test or scenario that does not exist.

## 12.5 Platform workflows in the factory pack

| Workflow | For | Slots | Hook points |
| --- | --- | --- | --- |
| `p.wf.corporate.v1` | Outward file and high-value payments | `scheme-leg` | `after-validate`, `enrich-before-screen` (from the segment), `before-release`, `on-close` |
| `p.wf.commercial.v1` | Outward instant payments | `scheme-leg` | The same four |
| `p.wf.inward.v1` | Every inward payment and return | `scheme-leg`, `scheme-refuse` | `on-close` |
| `p.wf.request.v1` | Requests and exceptions that are not payments | `scheme-leg` | `on-close` |
| `p.seg.check-and-screen.v1` | The shared check and screen stages | None | `after-validate`, `enrich-before-screen` |

`p.decide.workflow.v1` picks among them by kind, direction and segment (`p.table.workflow-select.v1`). The number of platform workflows is not fixed; these four are a starting set.

## 12.6 Known gaps

| Gap | Where | What closes it |
| --- | --- | --- |
| Aani message set, time limits and reason codes are not public | `uae.aani`, all artefacts | The AEP participant specification (D10) |
| WPS file types come from a 2018 guide | `uae.wps`, all artefacts | The current CBUAE WPS rulebook (D10) |
| Agent-side refund and return legs, and disbursement cancellation | `uae.wps` scheme manifest, four planned messages | Authoring after the rulebook is in hand |
| Return, recall and request-to-pay legs | `uae.aani` scheme manifest, three planned message groups | Authoring after the specification is in hand |
| ISO reason codes were written from memory | Every rule | A check against the current ISO external code set |
| Scripts-behind do not exist yet | Every script-bound activity and simulator | Build specs C24 to C26 |
| Budgets and waits are placeholders | Policies, deadlines, awaits | Scheme rulebooks and the instant-rail benchmark |
| Scheme validation runs first in the leg, after the reservation | `uae.wps.wf.salary-file-out.v1` | A decision on a pre-reserve scheme slot |
| Test samples are named but not written | Every test with an `inbound` sample under `samples/` | Build specs C25 and C26, with no personal data in any sample |
| Test traces are expectations written by hand; nothing has run them yet | Every test with a `trace` | The studio interpreter (C09) and the test runner (C11) |
| The `returned` exit outcome of the outward legs has no test | `uae.aani.wf.credit-out.v1`, `uae.wps.wf.salary-file-out.v1` | Build specs C25 and C26: add the test or remove the outcome |
| The supplementary file that pairs with a WPS payment file is awaited but not mapped | `uae.wps.wf.agent-payment-in.v1` | Build spec C25 |
