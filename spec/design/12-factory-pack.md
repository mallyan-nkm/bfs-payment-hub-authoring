# Part 12. Factory pack

Status: draft 0.1, 17 November 2026. Normative words follow RFC 2119.

## 12.1 Purpose

The factory pack is the default content that ships with the studio: the platform (`p`), the UAE cluster platform (`uae.p`), and one scheme (`uae.wps`). It gives a designer something real to open on day one, it is the worked example behind every part of this spec, and it is the fixture set for building the studio.

## 12.2 What it is and is not

| It is | It is not |
| --- | --- |
| Shared content with `origin: factory`, held to the same schemas and checks as any other | A separate mechanism or a special kind of artefact |
| Read-only to banks, like all shared content | A bank's content; a bank adds hooks and values on top |
| A complete set of contracts, rules, simulators, workflows and tests | A set of finished scripts; scripts-behind are authored against these contracts (C24, C25) |
| Confirmed for `p` and `uae.p` | Confirmed for the scheme; `uae.wps` is provisional until checked against its rulebook |

| R-12-13 | File encryption MUST be a port, `p.port.encryption.v1`, the pair of `p.port.decryption.v1`, with a simulator carrying the standard outward scenarios, and the activity `p.protect.encrypt-file.v1` behind it. | R-12-14 | The scheme pack MUST refuse a salary file whose employer the labour ministry has suspended (`uae.wps.rule.employer-not-suspended.v1`, in the salary file checks), with the employer's status a registered extension field written by a lookup behind a port (`uae.wps.enrich.employer-status.v1`, `uae.wps.port.labour-ministry.v1`). An employer with no known status MUST NOT be refused for it. It is the same for every bank, so it is not a bank rule. | The rule's examples; tests WPS-OUT-006, WPS-OUT-007, WPS-ENR-001, WPS-ENR-002 |
| R-12-15 | A bank that posts to its core banking by file MUST be able to bind `p.port.core-banking.v1` to the runtime's `file-bulk` adapter, with no workflow change: a batch of postings becomes one bulk file in the source's DE layout, put on core banking's landing folder through the bank's `p.port.file-transfer.v1`, submitted, its status read until core banking answers, and the lines it failed posted again in a file of their own (`repostAttempts`, `repostCodes`). The same batch MUST be the same file, never uploaded twice; a status never answered is an unknown fate, never posted blind. The adapter has a simulator. | `FileBulkCoreBankingTests` |
| R-12-16 | The labour ministry's establishment register MUST be reached through the bank's binding of `uae.wps.port.labour-ministry.v1`: on the runtime the `gateway-rest` adapter (its credential by reference) or the simulator; the native code-behind of `uae.wps.enrich.employer-status.v1` writes what it answers. A bank that has not said where its register is binds a placeholder host and no path, and every call is refused. | `FileProtectionAndRegisterTests`; tests WPS-ENR-001, WPS-ENR-002 |
| R-12-17 | On a scheme whose wire is a file, every file a bank sends MUST be encrypted through `p.protect.encrypt-file.v1` before it is sent, and a file the encryption service refuses MUST NOT be sent: the salary file, the receipt confirmation, the disbursement file, the returns file and the refund request. A file a bank receives encrypted is decrypted through `p.protect.decrypt-file.v1`. On the runtime both have a native code-behind on the bank's bindings (OpenPGP, or the source's GnuPG key folder as `gnupg`), and the file sent is the encrypted one. | Lint L45 (mutation M64); tests WPS-IN-001 to WPS-IN-009, P-DEC-001, P-DEC-002; `FileProtectionAndRegisterTests` |
| R-12-18 | A salary line's account type MUST be the one its channel declared at upload, where it declared one, and its bank's name MUST come from the scheme's participant directory (`uae.wps.table.participant-names.v1`, a value looked up by date) by the line's routing code. Shared content names no bank: the directory's default is empty. | Test WPS-MAP-005; the table's examples |

## 12.4 Contents

The pack is checked by three tools. `tools/validate.py` runs the schemas and the checks of Part 5. `tools/mutation_tests.py` breaks the pack once per check and expects the check to fire. `tools/build_docs.py` refuses to render if a build story cites an artefact, test or scenario that does not exist.

## 12.5 Platform workflows in the factory pack

| Workflow | For | Slots | Hook points |
| --- | --- | --- | --- |
| `p.wf.corporate.v1` | Outward file and high-value payments | `scheme-leg` | `after-validate`, `enrich-before-screen` (from the segment), `before-release`, `on-close` |
| `p.wf.commercial.v1` | Outward instant payments | `scheme-leg` | The same four |
| `p.wf.inward.v1` | Every inward payment and return | `scheme-leg`, `scheme-refuse` | `on-close` |
| `p.wf.request.v1` | Requests and exceptions that are not payments | `scheme-leg` | `on-close` |
| `p.seg.check-and-screen.v1` | The shared check and screen stages | None | `after-validate`, `enrich-before-screen` |

`p.decide.workflow.v1` picks among them by kind, direction and segment (`p.table.workflow-select.v1`). The number of platform workflows is not fixed; these four are a starting set.

## 12.6 Known gaps

| Gap | Where | What closes it |
| --- | --- | --- |
| WPS file types come from a 2018 guide | `uae.wps`, all artefacts | The current CBUAE WPS rulebook (D10) |
| Agent-side refund leg and disbursement cancellation | `uae.wps` scheme manifest, three planned messages | Authoring after the rulebook is in hand |
| ISO reason codes were written from memory | Every rule | A check against the current ISO external code set |
| Scripts-behind do not exist yet | Every script-bound activity and simulator | Build specs C24 and C25 |
| Budgets and waits are placeholders | Policies, deadlines, awaits | Scheme rulebooks and the instant-rail benchmark |
| Scheme validation runs first in the leg, after the reservation | `uae.wps.wf.salary-file-out.v1` | A decision on a pre-reserve scheme slot |
| Test samples are named but not written | Every test with an `inbound` sample under `samples/` | Build spec C25, with no personal data in any sample |
| Test traces are expectations written by hand; nothing has run them yet | Every test with a `trace` | The studio interpreter (C09) and the test runner (C11) |
| The `returned` exit outcome of the outward leg has no test | `uae.wps.wf.salary-file-out.v1` | Build spec C25: add the test or remove the outcome |
| The supplementary file that pairs with a WPS payment file is awaited but not mapped | `uae.wps.wf.agent-payment-in.v2` | Build spec C25 |
| No leg fills the slot of the instant workflow, and no handler is left | `p.wf.commercial.v1`, the `handler` workflow kind | Issue I-38 in `docs/ISSUES.md` |
