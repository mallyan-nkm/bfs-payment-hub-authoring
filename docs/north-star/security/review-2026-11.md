# Security review, November 2026

A review of the whole repository on 22 November 2026: the studio, the runtime, the Temporal SQL Server plugin, CI, the dependencies, the container images and the committed content. Every finding is fixed in code with a regression test, or recorded as an Issue and a Recommendation where a fix needs the owner (I-119 to I-124). The threat model (`threat-model.md`) is updated to match.

This repository is public. Each finding says where it was and what changed, no more than its owner needs (`secure-coding.md`, "A vulnerability").

## Scope and method

| Surface | What was read | What was run |
| --- | --- | --- |
| Studio server | `studio/src/server` (HTTP, sign-in, sessions, CSRF), every route of `api.ts` against the permission table and the tenant, `content/`, `import/`, `export/zip.ts`, `testing/runner.ts`, `ai/agent.ts` | The unit suite, the black-box sign-in, API and browser suites |
| Script sandboxes | `interp/sandbox.ts`, `interp/pysandbox.ts`, `interp/py_harness.py` | Escape attempts as tests |
| Runtime | `TransactHub.Auth`, the release API, `TransactHub.Native`, the operations, service and test bench hosts, `TransactHub.Security`, package and bundle readers, backup and restore, telemetry masking | `dotnet test TransactHub.Runtime.slnx` |
| Temporal SQL Server plugin | `sqlplugin/sqlserver/query_converter.go`, `visibility.go` and the query builders | `go test` of the converter; govulncheck |
| CI | `.github/workflows/*.yml` | The pinning check below |
| Dependencies | `studio/package-lock.json`, the runtime's NuGet graph, `runtime/temporal-mssql/go.mod` | `npm audit`, `dotnet list package --vulnerable --include-transitive`, govulncheck |
| Content and history | the tree and 197 commits | A pattern scan for keys and tokens, a scan for internal hosts and addresses |

The OWASP ASVS 4.0.3 level 2 chapters that apply were walked for each surface: V2 and V3 (authentication, sessions), V4 (access control), V5 (validation, injection, deserialisation), V7 (logging), V8 (data protection), V9 (communications), V10 (malicious code), V12 (files), V13 (API), V14 (configuration).

## Findings

Severity is the impact if exploited in a shared installation, with the likelihood a reachable caller gives it. Every finding below is fixed in this change unless its last column names an Issue.

### Reviewed, nothing found

| Surface | What was checked |
| --- | --- |
| SQL injection, Temporal plugin | Every value of a visibility query reaches T-SQL through `tsqlString`, which doubles every quote after undoing the shared converter's MySQL escapes; column names come from the search attribute registry; paging values are parameters. A regression test feeds quotes, backslash runs, `U+02BC`, NUL and LIKE metacharacters through all four literal paths and checks each comes out as one literal (`TestQueryConverterKeepsEveryValueInsideOneLiteral`). |
| SQL injection, runtime | EF Core only; `NeutralityTests` refuses raw SQL. |
| Deserialisation | Studio YAML is `yaml` 2 with its alias limit and no custom tags; JSON is `JSON.parse`; runtime YAML is YamlDotNet with no type tags; no binary formatter anywhere. |
| CORS | No host sends CORS headers, so a browser on another origin reads nothing. |
| Cookies | The session and sign-in cookies are signed, `HttpOnly`, `SameSite=Lax`, `Secure` over https; CSRF tokens on every change. |
| SSRF | Every URL a host fetches (GitHub API base, OIDC issuer and its JWKS, the package source, Vault, Key Vault, AWS) comes from the deployment's configuration, never from a request; the assistant has no URL tool. |

| Secrets, history and tree | 197 commits scanned for private keys, AWS, GitHub, Slack, Google and Anthropic tokens: none. Every host name in content and code is `.invalid`, `example`, loopback or a public API. The CI job `secret-scan` runs gitleaks 8.21.2 on every push. |

| Container images | The observability stack pins each image by tag and digest and binds every port to 127.0.0.1. |

## Follow-up, 23 November 2026

The owner accepted the recommendations of I-119, I-120, I-121 and I-124, and decided I-139 (shorter sealed sessions with a heartbeat) and that the studio is multi-tenant while the runtime is single-bank. Built in one change, each with its tests:

| Issue | What changed | Requirement | Check |
| --- | --- | --- | --- |
| I-119 | Every script-behind runs in a worker process with nothing of the studio in it: empty environment, no file, no network (namespace on Linux), Node permission model or Python audit hook and Landlock, memory and time limits, JSON over stdio | R-08-20 | `script-isolation.test.ts` |
| I-120 | Every read of a bank's user is answered from the bank's view of the studio, the assistant's tools among them; a bank's scripts and samples are its own | R-11-48 | `tenant-isolation.test.ts` |
| I-121 | The worker's own client-credentials token for the native host; mutual TLS as an option, certificates by reference; the engine hosts take their callers' token | R-08-21, R-08-22 | `native-auth.test.ts`, `NativeHostMutualTlsTests`, `HostTokenTests` |
| I-124 | No "allow always" for `save_sample`; an assistant's sample goes into the change set for its checker; an instruction in a tool result is shown in the panel | R-11-49 | `assistant-injection.test.ts` |
| I-139 | Sessions checked with the provider every 5 minutes by refresh token; 8 hours, 30 minutes idle, 1 hour for the command line | R-11-50 | `sessions.test.ts` |

What remains: I-147 (a platform without namespaces or Landlock) and I-148 (refresh token rotation across instances).

## What this review did not do

- No penetration test of a deployed installation, and no test against a real identity provider, Key Vault or AWS account (I-105).
- The full govulncheck of the plugin's `cmd/` (the Temporal server itself) did not finish in the review's sandbox for memory; the CI job runs it (I-123).
- gitleaks was not run inside the review's sandbox, which refuses commands named like `git`; the history was scanned by pattern instead, and CI runs gitleaks on every push.
