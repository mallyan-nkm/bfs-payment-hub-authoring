# FAB: the bank's configuration (platform only)

FAB's configuration, mined from the TransactHub source (the `PaymentHub` repository this runtime converges, plan W6). It lives here by the owner's decision of 2026-11-22, which amends D5 for ADIB, ENBD and FAB as it did for DIB on 2026-11-21 (`docs/runtime/NSTAR-CONVERGENCE-PLAN.md` section 8). Its tests use synthetic payments only.

Shared content names no bank. The tenant id `fab` is in `spec/tools/deny-names.txt`, so check L09 refuses it in shared content, and `runtime/tests/TransactHub.Store.Tests/BankConfigurationTests.cs` refuses the bank's name in shared code (`FAB`, `Fab`, the full name).

## FAB does not run WPS in the source

The source has no deployment of FAB: no customer overlay in `infra/docker/` (there are overlays for DIB and ADIB only), no licence, and no WPS parameter seeded for it. Its only workflows are two IPI drafts, `dsl/workflows/fab-ipi-inward.v1.workflow.json` and `fab-ipi-outward-initiate.v1.workflow.json` (1.0.0, `approval_status: draft`, `bank_id: fab`). It has a set of bank plugins, `services/activities/bank/Fab/` (Core, Ipi, Fts, Wps, Npss, Edda, Cbft), ported from a compiled worker; every core-banking route they call is the bank simulator's. The encryption library's sample settings name FAB (`services/shared/dotnet/PaymentHub.Encryption/appsettings.sample.json`: profiles `WPS_SalaryUpload` and `WPS_SIFUpload`, keys `FabWpsSalary` and `FabWpsSif`, encrypt only), but they are a sample with placeholder fingerprints, not the bank's deployment. The plan calls FAB a thin stub (W6). The participant directory lists the bank as a WPS, IPI and FTS participant (`ParticipantBanks`), which says what the scheme knows of the bank, not what the bank runs on this platform. So this folder configures the platform only (Issue I-86).

## What became what, and why

- **Rail values.** The bank runs none of the factory's rails, so `enabledRails` is the empty list: the factory's default, set here so that the choice is on record with its source. BANK-RAIL-001 shows a payment that asks for WPS finds no rail; `studio/test/platform-bank-packs.test.ts` runs a salary file through `p.wf.corporate.v1` for the bank and it is refused at routing, before anything is sent.
- **No routing code.** The source has none for the bank, so `uae.wps.rule.agent-is-this-bank.v1#ownRoutingCodes` keeps the factory default, none (BANK-RTE-001).
- **Port binding.** The source holds no gateway setting of the bank's, so the binding carries a `.invalid` host and the credential by reference, and nothing else. The runtime's adapter refuses every call until the bank's settings are added, so no payment of the bank posts to a simulator or to a guessed host (Issue I-85, `PlatformOnlyBankFolderTests`). The bank's settings come as a new binding with a later `validFrom`.
- **Hooks, built but switched off.** No workflow and no test of the source calls `FabWpsEmployerAmlCheck` or `FabMohreNotifyResult` (`tests/PaymentHub.UnitTests/Activities/FabPluginTests.cs` covers only the WPS reversal of the fork). So the shipped `bindings` is empty. Each hook is complete (hook, activity, script-behind, bank port, simulator), and BANK-AML-001, BANK-AML-002 and BANK-NTF-001 run each alone. `studio/test/platform-bank-packs.test.ts` binds both, with WPS switched on, in a test-only configuration and runs a synthetic salary file end to end, and fails if either is bound in the shipped `configuration-set.yaml`. To switch them on, the bank first needs WPS (the rail, its routing code, its core-banking settings and its WPS bindings), then adds the two bindings given in `../adib/README.md` ("To switch them on") with its own `validFrom`, and changes that test in the same change.
- **No bank rule.** `FabValidateWpsRules` is the same rule as in each bank's fork; the plan makes it one `uae.wps` rule (Issue I-88).

## What a deployment must set

- The bank's core-banking settings, as a new binding of `p.port.core-banking.v1` with a later `validFrom`: `baseUrl` (a `.invalid` placeholder here), `balancePath`, `postingPath`, `balanceFunctionId`, `postingFunctionId`, `serviceCode`, `externalHostId`, `txnFlag`, `uploadBranch`, `balanceFlag`, `authStatus`, and `referencePrefix` if the bank has one (I-85).
- `TH_FAB_CORE_BANKING_TOKEN`.
- Where the AML screening and labour ministry services are, if their hooks are bound.
