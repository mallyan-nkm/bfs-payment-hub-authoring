# Content and configurations

What the studio publishes and what a bank configures (plan section 2, W4, W6, W8). This folder, on the branch the studio is connected to (`TH_CONTENT_REPO`, `TH_CONTENT_BRANCH`), is the studio's only store (R-11-21): it reads it through the GitHub API into memory and keeps no other copy. The runtime's pipeline reads it too (`POST /import-branch`). Nothing here is rewritten once published (R-09-21, R-11-23); the two exceptions, `governance/users.yaml` and `governance/settings.yaml`, change only by a reviewed commit (Issue I-44).

| Folder | What | Who writes it |
| --- | --- | --- |
| `artefacts/<scope>/<name>/<release>.yaml` | Each published document at its release. The factory packs (`p`, `uae.p`, `uae.wps`), the engine bindings and the supersession example are seeded here from `spec/` (R-11-25): their first line says `Generated by` and names the source. Never edit them by hand. | The studio, on publish; the seed |
| `artefacts/<scope>/tests/<id>.yaml` | A test case. | The studio, on publish; the seed |
| `releases/<scope>/<name>/<release>/<target>/` | A released package of a workflow, for one engine. Written once, never changed. | The studio, on publish |
| `releases/distributions/<bank>/<distribution id>/`, `releases/configuration/<bank>/<release>/` | A bank's signed distribution (every pack release the bank runs, for one engine) and its signed configuration release (values, port bindings, reference tables), each tagged; a runtime installs them from here (`docs/runtime/PACKAGING-AND-DEPLOYMENT.md`). | The studio, on approval |
| `change-sets/<id>.yaml` | What was published together, by whom, approved by whom; a waiver's change set holds the waiver. | The studio, on publish |
| `audit/change-sets/<id>.yaml` | Every event of a change set, from its first draft to its publish, each record hashing the one before. | The studio, on publish |
| `audit/events/<date>/<time>-<hash>.yaml` | One event that is part of no change set (a refusal, a retirement, a configuration edit). | The studio |
| `governance/users.yaml` | The studio's users and roles. Changed only through maker-checker. | The studio |
| `governance/settings.yaml`, `governance/in-flight/` | How the studio publishes (mode, engine target, environment); in-flight counts from operations. | The studio |
| `samples/`, `scripts/` | Synthetic samples and script-behinds a designer added. | The studio |
| `supersessions/` | The supersession example; `handed-over/` holds supersessions handed to operations. | The seed; the studio |
| `environments/<env>/activations/` | From when a release is the one new payments take. | The studio, or operations |
| `banks/<bank>/` | A bank's configuration: its bank pack, rule values, hook bindings, port bindings, effective-dated. The studio adds `artefacts/`, `configuration-sets/` and `scripts/` for what it publishes for the bank. | The bank, through the studio's maker-checker |
| `extractions/` | Extraction bundles to import. Not read by the studio as content. | People |

A change set in progress is not in this folder of the content branch: it is its own branch, `studio/<change set id>`, which holds its drafts at the paths above, their scripts and its audit, one commit per draft save (R-11-22). Approval publishes it here as one commit, or, in pull-request mode, opens a pull request from that branch.

Values here are synthetic, with one exception. By the owner's decision of 2026-11-21 (D5 as amended), DIB's real configuration lives here, in `banks/dib/`: its bank pack, its configuration set, its core-banking binding and its CBX values. Its `README.md` says where each value came from and what is not carried. By the owner's decision of 2026-11-22, ADIB, ENBD and FAB are set up the same way, in `banks/adib/`, `banks/enbd/` and `banks/fab/`: none of them runs WPS in the source, so each configures the platform only, and its `README.md` says where each value came from and what has nowhere to go yet. Another bank's real values (its routing code, GL accounts, host ids) still live in the bank's own copy of this repository. No secret lives here, DIB's included: a secret is named by reference and set at deployment.

| Bank folder | What |
| --- | --- |
| `banks/example-bank/` | Synthetic. Every knob the runtime reads, with made-up values, and the example bank pack seeded from `spec/examples/bank/`. |
| `banks/dib/` | DIB's real configuration. The studio loads its pack with `--bank dib`. |
| `banks/adib/` | ADIB's real configuration for WPS (Issues I-86, I-116). The studio loads it with `--bank adib`. |
| `banks/enbd/`, `banks/fab/` | ENBD's and FAB's real configuration, platform only (Issues I-85, I-86). The studio loads each with `--bank <name>`. |
